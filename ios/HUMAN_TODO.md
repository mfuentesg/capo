# Things only a human can do

1. **Redirect URL (done).** Production Supabase, Auth, URL Configuration: add `capo://auth/callback` to Redirect URLs. Locally, `supabase/config.toml` already lists it; restart the stack after changing it (`pnpm supabase stop && pnpm supabase start`).
2. **Local login is Google only.** Local Google OAuth needs `SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID` and `SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET` in your shell environment before starting the stack. To skip the browser step in Debug builds, run `ios/scripts/mint-dev-session.sh [email]` (local stack only; it writes the git-ignored `ios/Capo/Capo/DevSession.plist`; `--remove` deletes it). Email and password sign-in exists as a fallback in non-production builds.
3. **Pick a backend.** `ios/scripts/use-supabase.sh local [--device]`, or create `ios/Capo/Secrets.production.plist` (copy `Secrets.example.plist`) and run `ios/scripts/use-supabase.sh production`. A physical device with the local stack needs the Mac and device on one LAN, incoming connections allowed in the macOS firewall, and the iOS Local Network prompt accepted.
4. **Sign in with Apple (code done, setup pending, release blocker).** The app side is in place: the Apple button on the auth screen, `ASAuthorizationController` with a SHA-256 nonce into `signInWithIdToken(.apple)`, and `ios/Capo/Config/Capo.entitlements` (`com.apple.developer.applesignin`). Still yours: (a) in the Apple Developer portal enable Sign in with Apple on App ID `com.mfuentesg.capo` (Xcode's automatic signing registers the capability on a paid team, so the first signed build may fail until you open the project once and let it update the profile); (b) create a Services ID and a Sign in with Apple key; (c) in Supabase (production, and local `supabase/config.toml` if you want it there) enable the Apple provider and add `com.mfuentesg.capo` to "Authorized Client IDs" (native flow, so no web redirect is needed); (d) test on a device, since the simulator needs an iCloud account. Apple only returns the name on the first authorization; the app stores it in the user metadata then.
5. **Account deletion (code done, decision pending).** `delete_user_account` now ships in every build. Deleting cascades to teams the user created (`MIG/20260311185040_add_delete_user_account_function.sql`), removing other members' content; the dialog warns when the user owns teams with other members. Decide whether to require an ownership transfer first (open question 6 in `ios/docs/GAP_ANALYSIS.md`) or keep the warning only.
6. **CI and PR.** The branch `feat/ios-p0-golden-fixtures` is pushed; no PR is open. Confirm a macOS runner image with Xcode 26 or newer (`macos-26`) and the extra Actions minutes, then open the PR yourself.
7. ~~Universal links~~ Dropped: shared and invitation links stay web-only.
8. **App Store Connect.** Create the app record, fill the privacy nutrition labels and review `PrivacyInfo.xcprivacy`.
9. **Devices.** Keep Developer Mode enabled on both devices and the signing team logged in to Xcode.
10. **Feedback.** The in-app form inserts straight into the `feedback` table (the same RLS policy as the web). The web's server action also emails a notification through Resend; a direct insert cannot, so decide whether you want that email for app feedback (it would need an Edge Function or a database webhook).
