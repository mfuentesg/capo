# Capo for iOS and iPadOS

Native SwiftUI app (iOS 17+, iPhone and iPad). It talks directly to Supabase under the existing RLS and reads everything from a per-user local SQLite database, so the library, songs and setlists work offline. The design is in `ios/docs/PLAN.md`.

## Layout

- `Capo/Capo.xcodeproj` is the app target. It links one local package product, `CapoAppKit`.
- `Packages/` holds five local SwiftPM packages (CapoUI is split into CapoDesign, CapoIcons, CapoRendering, CapoAuthUI, CapoShellUI, CapoLibraryUI, CapoPerformanceUI, CapoPlaylistsUI, CapoEditorUI, CapoChordsUI, CapoTeamsUI and CapoSettingsUI): `CapoCore` (models, contracts, ChordPro engine, fakes), `CapoData` (GRDB store and sync engine), `CapoSupabase`, `CapoUI` (design system and screens) and `CapoAppKit` (composition).
- `Fixtures/` holds the ChordPro corpus and the golden JSON generated by the web code. The Swift port must match them exactly.
- `i18n/` holds iOS-only strings. `scripts/gen-i18n.mjs` merges them with `lib/i18n/locales/*.json`.

## Build, run, test

Needs Xcode 26 or newer.

```bash
ios/scripts/build-sim.sh            # app for the simulator, unsigned (derived data in ios/build/dd-sim)
ios/scripts/test-packages.sh        # swift test for CapoCore, CapoData, CapoSupabase, then CapoUI on a simulator
ios/scripts/install-device.sh [iphone|ipad]   # signed build, install and launch on a connected device
```

Or from the repo root: `pnpm ios:build`, `pnpm ios:test`.

Open `ios/Capo/Capo.xcodeproj` in Xcode and run the `Capo` scheme.

## Backend configuration and demo mode

The app reads `ios/Capo/Capo/Secrets.plist` (git-ignored) with `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `CAPO_WEB_URL` and `CAPO_ENV_NAME`. `ios/Capo/Secrets.example.plist` shows the shape.

```bash
ios/scripts/use-supabase.sh local             # simulator against the local stack (pnpm supabase start)
ios/scripts/use-supabase.sh local --device    # physical device, uses the Mac LAN IP
ios/scripts/use-supabase.sh production        # copies ios/Capo/Secrets.production.plist (you create it)
ios/scripts/use-supabase.sh demo              # removes Secrets.plist
```

Without a `Secrets.plist` the app starts in demo mode with in-memory sample data. Launch with `-CapoDemoMode YES` to force it. Sign-up is offered only when `CAPO_ENV_NAME` is not `production`.

For local debugging, `ios/scripts/mint-dev-session.sh` writes a git-ignored `DevSession.plist` so Debug builds sign in as an existing local user without the Google browser step. It only works against `127.0.0.1`.

## Navigation and debug launch arguments

One shell for iPhone and iPad: slim top bar plus a bottom bar (Songs, Playlists, Chords, Teams). Settings opens from the avatar menu. Debug builds accept launch arguments for simulator checks: `-CapoDemo YES` (demo data), `-CapoSidebar songs|playlists|chords|teams|settings` (start tab), `-CapoOpenFirstSong YES`, `-CapoOpenDraft YES` (queue three songs, open the draft dialog), `-CapoFloatingOpen YES` with `-ios.stage.floatingControls YES` (floating controls, panel open), `-CapoStageFullscreen YES`, `-CapoSettingsTab appearance|account`, `-CapoDebugPalette`, `-CapoDebugFont`, `-CapoDevSession YES`.

Production is configured with `ios/scripts/use-supabase.sh production`; the app then reads and writes the real account. Status and open items: `ios/docs/STATUS.md`.

## Localization

`node ios/scripts/gen-i18n.mjs` regenerates `Localizable.xcstrings` and `L10n.swift` in `CapoDesign` (`pnpm ios:i18n`). `--check` fails when they are stale (`pnpm ios:i18n:check`, also run in CI). Use `L10n` in code; add iOS-only strings to `ios/i18n/ios.{en,es}.json` under `ios.*`.

## Golden fixtures

Regenerate with `UPDATE_GOLDEN=1 node_modules/.bin/jest --testPathPatterns=golden` after an intentional change to `features/lyrics-editor/utils`, `lib/music-theory.ts` or the corpus, then update the Swift port until its golden tests pass.

## Conventions

- Swift Testing for tests; fixtures are found through `#filePath`.
- Features depend on protocols from `CapoCore`; `CapoFakes` provides in-memory implementations for previews and demo mode.
- See `ios/docs/wp-notes/` for per-work-package notes and deviations.
