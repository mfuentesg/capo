## WP11 notes

- `SettingsView()` keeps its frozen init. Shell-provided data arrives through a new public environment value, `SettingsContext` (`\.settingsContext`, defined in `CapoSettingsUI/SettingsContext.swift`): email, name, avatar, provider, environment name, server URL, `isDemo`, `signOut(erase:)` and an optional `deleteAccount` closure.
- **Shell TODO (A0/WP5):** inject `.environment(\.settingsContext, SettingsContext(...))` where `SettingsView()` is created (`MainShellView.swift`, in `ShellEnvironment`). `signOut` should call `SessionStore.signOut(erase:)` directly; Settings shows its own confirmation (and the pending-ops warning). Without the injection the screen shows an empty account and no-op sign out.
- **Delete account:** no contract exists for `delete_user_account`, so the button is shown only when `SettingsContext.deleteAccount` is non-nil. The shell should pass nil in production builds. After a successful call Settings calls `signOut(true)`. A0 needs to implement the closure (e.g. `client.rpc("delete_user_account")`) in CapoAppKit.
- Theme and lyrics columns go through `SettingsRepository.updatePreferences`; the shell already applies the theme from the `preferences()` stream (`ShellModel`), so no extra wiring.
- Language shows the current app language and opens the iOS Settings app (per-app language).
- Sync section: status label, last sync, pending count, "Sync now", conflicts link via `capoActions.showConflicts`.
- Strings: existing `L10n` keys where possible; new `ios.settings.*` strings use `String(localized:defaultValue:bundle: .capoDesign)` with `// TODO(i18n)` for WP12 to harvest.
- No tests: the CapoUI manifest has no CapoSettingsUI test target (manifests are frozen).
